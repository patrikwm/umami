# Deploying Umami to Coolify

[Coolify](https://coolify.io/) is an open-source, self-hostable platform-as-a-service (PaaS) alternative to Heroku, Netlify, and Vercel. This guide shows how to deploy Umami on Coolify using Docker Compose.

## Prerequisites

- A Coolify instance set up and running
- A domain or subdomain configured in Coolify (e.g., `analytics.yourdomain.com`)

## Docker Compose Configuration

Create a new Docker Compose service in Coolify with the following configuration:

```yaml
services:
  umami:
    image: 'ghcr.io/umami-software/umami:postgresql-latest'
    ports:
      - '3000:3000'
    environment:
      - SERVICE_URL_UMAMI_3000
      - 'DATABASE_URL=postgres://$SERVICE_USER_POSTGRES:$SERVICE_PASSWORD_POSTGRES@postgresql:5432/$POSTGRES_DB'
      - DATABASE_TYPE=postgresql
      - APP_SECRET=$SERVICE_PASSWORD_64_UMAMI
      - AUTH_SECRET=$SERVICE_PASSWORD_64_UMAMI
      - AUTH_URL=$SERVICE_FQDN_UMAMI_3000
      - OIDC_AUTO_CREATE=true
      - DISABLE_LOCAL_LOGIN=false
    depends_on:
      postgresql:
        condition: service_healthy
    healthcheck:
      test:
        - CMD
        - curl
        - '-f'
        - 'http://127.0.0.1:3000/api/heartbeat'
      interval: 5s
      timeout: 20s
      retries: 10
  postgresql:
    image: 'postgres:16-alpine'
    volumes:
      - 'postgresql-data:/var/lib/postgresql/data'
    environment:
      - POSTGRES_USER=$SERVICE_USER_POSTGRES
      - POSTGRES_PASSWORD=$SERVICE_PASSWORD_POSTGRES
      - 'POSTGRES_DB=${POSTGRES_DB:-umami}'
    healthcheck:
      test:
        - CMD-SHELL
        - 'pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}'
      interval: 5s
      timeout: 20s
      retries: 10
volumes:
  postgresql-data:
```

## Environment Variables

📖 **See [Environment Variable Reference](./coolify-env-reference.md) for complete documentation.**

Coolify automatically provides several variables that are used in this configuration:

| Variable | Description | Example |
|----------|-------------|---------|
| `$SERVICE_FQDN_UMAMI_3000` | Fully qualified domain name for the Umami service | `https://analytics.yourdomain.com` |
| `$SERVICE_URL_UMAMI_3000` | Internal service URL | Auto-generated by Coolify |
| `$SERVICE_USER_POSTGRES` | PostgreSQL username | Auto-generated by Coolify |
| `$SERVICE_PASSWORD_POSTGRES` | PostgreSQL password | Auto-generated by Coolify |
| `$SERVICE_PASSWORD_64_UMAMI` | Base64-encoded secret | Auto-generated by Coolify |
| `$POSTGRES_DB` | Database name | `umami` (default) |

### Required Environment Variables

The following environment variables are **required** for Umami to work properly:

- **`AUTH_SECRET`**: Secret key for Auth.js session encryption (reusing `$SERVICE_PASSWORD_64_UMAMI`)
- **`AUTH_URL`**: Public URL where Umami is accessible (automatically set to `$SERVICE_FQDN_UMAMI_3000`)
- **`APP_SECRET`**: Secret key for Umami application encryption (reusing `$SERVICE_PASSWORD_64_UMAMI`)
- **`DATABASE_URL`**: PostgreSQL connection string

### Optional Environment Variables

- **`OIDC_AUTO_CREATE`**: Automatically create user accounts on first OIDC login (default: `true`)
- **`DISABLE_LOCAL_LOGIN`**: Disable username/password login, forcing OIDC-only authentication (default: `false`)

## Deployment Steps

1. **Create a new Docker Compose service** in your Coolify dashboard
2. **Paste the docker-compose configuration** above
3. **Configure your domain** in Coolify service settings (e.g., `analytics.yourdomain.com`)
4. **Set environment variables** if needed (Coolify auto-generates most of them)
5. **Deploy the service**

## First Login

After deployment, Umami will automatically create a default admin account:

- **Username**: `admin`
- **Password**: `umami`

⚠️ **Important**: Change the default password immediately after first login!

## Configuring OIDC (Optional)

If you want to enable OIDC authentication (Google, GitHub, Keycloak, Authentik, etc.), add the following environment variables to the `umami` service:

### Example: Google OAuth

```yaml
environment:
  - AUTH_GOOGLE_ID=your-google-client-id
  - AUTH_GOOGLE_SECRET=your-google-client-secret
```

### Example: GitHub OAuth

```yaml
environment:
  - AUTH_GITHUB_ID=your-github-client-id
  - AUTH_GITHUB_SECRET=your-github-client-secret
```

### Example: Generic OIDC Provider

```yaml
environment:
  - OIDC_NAME=Authentik
  - OIDC_ISSUER=https://auth.example.com/application/o/umami/
  - OIDC_CLIENT_ID=your-client-id
  - OIDC_CLIENT_SECRET=your-client-secret
  - OIDC_AUTH_URL=https://auth.example.com/application/o/authorize/
  - OIDC_TOKEN_URL=https://auth.example.com/application/o/token/
  - OIDC_USERINFO_URL=https://auth.example.com/application/o/userinfo/
```

For more details on OIDC configuration, see the [OIDC documentation](../oidc/README.md).

## Troubleshooting

### UntrustedHost Error

If you see errors like:

```
[auth][error] UntrustedHost: Host must be trusted. URL was: https://0.0.0.0:3000/api/auth/session
```

**Solution**: Ensure both `AUTH_SECRET` and `AUTH_URL` environment variables are set. The `AUTH_URL` should match your public domain (e.g., `https://analytics.yourdomain.com`).

Alternatively, for development/testing only, you can add:

```yaml
environment:
  - AUTH_TRUST_HOST=true  # Not recommended for production
```

### Database Connection Issues

If the Umami container can't connect to PostgreSQL:

1. Check that the `postgresql` service is healthy: `docker-compose ps`
2. Verify the `DATABASE_URL` format is correct
3. Ensure the `depends_on` with `service_healthy` condition is set

### Migration Issues

If database migrations fail on first deployment, check the logs:

```bash
docker-compose logs umami
```

The build process should automatically run migrations. If they fail, you may need to manually trigger them or check database permissions.

## Advanced Configuration

### Using External PostgreSQL

If you have an existing PostgreSQL database, remove the `postgresql` service and update the `DATABASE_URL`:

```yaml
services:
  umami:
    image: 'ghcr.io/umami-software/umami:postgresql-latest'
    ports:
      - '3000:3000'
    environment:
      - DATABASE_URL=postgresql://username:password@external-db-host:5432/umami
      - APP_SECRET=$SERVICE_PASSWORD_64_UMAMI
      - AUTH_SECRET=$SERVICE_PASSWORD_64_UMAMI
      - AUTH_URL=$SERVICE_FQDN_UMAMI_3000
    # Remove depends_on section
```

### Adding Redis for Session Storage

For better performance with OIDC authentication, add Redis:

```yaml
services:
  umami:
    environment:
      - REDIS_URL=redis://redis:6379
    depends_on:
      - redis
      - postgresql

  redis:
    image: 'redis:7-alpine'
    volumes:
      - 'redis-data:/data'
    healthcheck:
      test: ['CMD', 'redis-cli', 'ping']
      interval: 5s
      timeout: 3s
      retries: 5

volumes:
  postgresql-data:
  redis-data:
```
